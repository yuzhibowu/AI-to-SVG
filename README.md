# AI转SVG 0.6.4

一个离线的 Mac 原生小工具，把 Human Pictogram AI 素材页中的人物与道具提取为独立、透明背景的 SVG。

支持拖入多个 AI 文件或文件夹，自动跳过 HTML 说明文件，保留人物头部、身体和衣服细节。默认将所有 SVG 放在同一个文件夹，也可按原文档分文件夹，两种方式都支持 ZIP 打包。已有导出文件和同名文件夹不会被覆盖。

## 下载安装

在 [GitHub Releases](https://github.com/yuzhibowu/AI-to-SVG/releases/latest) 下载 DMG，打开后将「AI转SVG」拖入「Applications」安装。适用于 Apple Silicon，要求 macOS 13 或更新。

## 使用

导出时会显示实时进度条、已完成数量、百分比和当前文件名。ZIP 打包会继续显示打包与保存阶段，保存成功后弹出「导出完成」，可点击「在 Finder 中查看」。左侧「素材」旁的「清空」按钮可一次移除导入列表和识别结果，不删除原始 AI 或已导出的文件；处理中暂时禁用。

打开 `outputs/AI转SVG.app`，点击「用示例试试」可读取你提供的 `p0941.ai`，产生 8 个独立人物。也可以拖入多个 AI 文件，或包含素材的整个文件夹。

- 勾选需要的人物，点击黑色、黄色等常用色，或通过「自选颜色」和 HEX 色值选任意颜色。颜色统一作用于所有文档中勾选的图标，预览即时更新；「原色」恢复素材颜色。
- 顶部「导出方式」默认「全部放在同一个文件夹」，所有 SVG 直接保存到所选目录，按素材名称和图标编号排列，例如 `p0008_走る人-04.svg`。重名自动加 `(2)` 等后缀，已有文件不会被覆盖。
- 可切换「按原文档分文件夹」，沿用原来的归类方式。点击「导出 N 个 SVG」选择保存目录，一个图标一个 SVG。「ZIP 打包」也使用当前导出方式。
- 点击「ZIP 打包」将所有勾选的图标按当前导出方式保存到一个 ZIP。中文名称使用 UTF-8，包内只含 SVG；不附带 Mac 隐藏说明文件。ZIP 采用存储方式打包，不依赖外部转换或压缩程序。
- 自动识别遗漏时，使用「修正识别 → 补选人物」，点选或拖框选择人物路径。右侧实时显示结果。
- 需要合并时，先勾选当前文档中的多个图标，再使用「修正识别 → 合并当前所选图标」。
- 右键点击图标，可「编辑人物路径」、「拆分图标」或「删除」；删除只移除当前结果，不改动原 AI，支持撤销。拆分时框选一个完整人物，包含头部和身体；其余路径留在原图标中。
- 「修正识别 → 撤销上次修改」支持最近 30 次人物修改。保存修改后编号保持稳定，新图标使用新编号，可能出现编号间隔。

背景和镂空始终透明，棋盘格只是预览辅助。用户手动选中的网站标识等路径也会被导出，请检查右侧结果。

当前构建针对 Apple Silicon，运行要求 macOS 13 或更新。应用使用本机临时签名，尚未使用开发者证书签名和公证。

## 支持范围

引擎直接解析 Illustrator 8 兼容 PostScript AI 中的分组、直线、三次贝塞尔曲线、实色填充、复合路径和描边，不执行 PostScript 程序。描边按原宽度、端点和连接样式转成矢量轮廓；`R` 描边叠印标记也已识别。指令含义参考 [Adobe Illustrator 文件格式规范](https://13thmonkey.org/documentation/fonts/AI7FileFormat.pdf)。

Human Pictogram 素材使用定位十字和原始绘制分组来区分图标与页眉、署名。优先保留原作者的整个图标分组，不再要求只有一个圆形头部、所有部件同色，或人物必须由单条大身体路径组成。足球、独立手臂、帽子、装备、同一场景里的多人、单条复合路径人物，以及放在定位格外的额外变体都能保留。定位格用于判断归属，不会裁掉越界路径。没有定位格的旧素材仍使用分组与头身匹配，并可手动修正。

PDF 型 AI 新增兼容：使用 macOS [CGPDFScanner](https://developer.apple.com/documentation/coregraphics/cgpdfscanner) 读取单页纯矢量填充、复合轮廓、实色和仿射变换，已验证下载素材中的 p0933 踏板车。不是通用 PDF 转换器；PDF 描边、文字、图片、渐变、局部剪切、透明度和混合效果仍明确报错。旧版 AI 中未支持的绘图操作也不会静默跳过。

SVG 由矢量路径组成，无位图或外部资源。复合路径内的镂空保持透明；少量素材的白色遮盖路径转为矢量蒙版，按原始绘制顺序挖空，改色不会填死这些细节。蒙版里的白色矩形只用于定义透明度，不是导出背景。原色通过 macOS 的 CMYK → sRGB 转换，色彩配置可能导致细微色差。

本机下载目录的 1041 份 AI 全部通过解析并产生结果，原先 31 份描边报错和 1 份 PDF 报错均已修复。全库复查仍得到 7135 个图标，其中 11 份素材各排除两条误并的页脚版权路径。0.3.1 会排除远离人物且位于定位区域之外的小型独立分组，修复页脚版权符号被并入人物、撑大 SVG 范围的问题。完整的格外人物仍按原分组保留；小路径按所属原分组判断，避免误删头部和衣服细节。解析成功和路径守恒不能保证每个复杂场景的自动分组符合你的导出意图；需要拆开动作序列等情况，可用拆分、合并和删除调整。逐文件检查记录保存在 `outputs/素材检查结果.json`。

## 构建与检查

需要 Xcode 或 Swift 6 工具链，无第三方包和转换软件依赖。

```sh
zsh scripts/build-app.sh
CLANG_MODULE_CACHE_PATH="$PWD/work/module-cache" \
SWIFTPM_MODULECACHE_OVERRIDE="$PWD/work/module-cache" \
swift test --disable-sandbox --cache-path work/swift-cache --config-path work/swift-config --security-path work/swift-security
```

源码用 Swift Package Manager 管理，可在 Xcode 中打开 `Package.swift`。界面位于 `Sources/StickSVG`，解析、提取、人物修正和导出位于 `Sources/VectorEngine`。

24 项回归检查通过，覆盖跑步素材排除页脚版权符号并保留汗滴与公文包、格外独木舟的头部和船桨、原 p0941 的 8 人/20 条路径、踢球的 5 套完整人物与球、独立条纹手臂、原本椭圆的球、拳击描边、PDF 踏板车的轮子与帽子、9 套变体、跨多个定位格的动作组、格外人物、单条复合路径图标、白色镂空改色，以及批量导出、ZIP、手动编辑等已有行为。PDF 踏板车额外对照系统直接渲染的原页进行轮廓像素检查，轮廓交并比约 99.81%。

ZIP 记录实现参考 [PKWARE ZIP 格式规范](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)。

`Fixtures/*.ai` 是用户提供的测试素材，来源为 Human Pictogram 2.0，非本工具原创。内置示例用于本次本地开发和验证；若公开发布工具，应替换为允许随应用分发的自有示例。

## 应用图标

使用用户提供的黄色火柴人 Logo，保留原有黑色背景和透明区域。`Assets/AppLogo-source.png` 为原始附件，`Assets/AppIcon.png` 为 1024×1024 母版，原图等比缩放至 832 像素并居中，四周保留约 96 像素透明留白，使启动台中显示大小与相邻图标一致，`Assets/AppIcon.icns` 为应用图标。参照「通用控制结界」项目的 PNG-backed ICNS 格式，包含 16、32、64、128、256、512、1024 像素七档图层。`scripts/build-icon.swift` 可重复生成图标，构建应用时自动运行；应用资源和左上角 Logo 同步使用新图标。

### Keynote 文稿导出（0.5.4）

点击「导出 Keynote」，每份已勾选图标的 AI 文档生成一页，按素材名称和图标编号排序。每页保留完整主题名称，四五个图标放一排，更多图标自动换行，不截断数量。调色板颜色同样适用。

图标通过原始贝塞尔路径生成原生可编辑形状，每个图标独立成组；白色镂空转换为真实孔洞。可以从 Keynote 直接复制图标到无边记，无需先执行「拆分」。用足球（5 个）、跑步（4 个）、p0941（8 个）进行实际 Keynote 打开检查，直接粘贴到无边记后仍为包含圆形、形状的群组。

需要电脑安装 Keynote。首次导出可能显示 macOS 自动化授权，请允许 AI转SVG 控制 Keynote。应用先在本地建立可编辑 PowerPoint 文稿，再调用 Keynote 的文稿接口保存为 `.key`；不会保存或关闭用户原有文稿。导出时显示图标进度和 Keynote 保存阶段，完成后提示主题页数、图标数和保存位置。同名文稿自动加序号。最终只导出 .key 文件，中间文稿保存在应用私有缓存中，不放入导出目录。大批量素材会等待完整页数导入完成，最长等待 30 分钟，并显示已等待时长；单次文稿查询超时不再终止导入。仅在文稿保存并关闭成功后删除该次中间数据，避免破坏 Keynote 仍在读取的文件。

Keynote 导出默认使用纯黑背景与白色主题标题，图标保留所选颜色。

Keynote 导入与保存阶段显示动态等待指示和实时等待时长，不显示无法测量的百分比。

Keynote 文件打开使用系统 Launch Services，并检查打开回执；未收到回执或发生打开错误会立即说明原因，避免等待一个尚未打开的文稿。

### 剪贴板矢量导入（0.6.0）

在 Keynote 或无边记中复制形状后，点击左侧「从剪贴板导入」，或按 ⌘⇧V。导入结果进入现有预览、勾选、批量调色与 SVG/Keynote 导出流程。复制的每个顶层对象生成一个图标，成组对象保留完整路径与位置，白色填充按真实颜色保留。

当前优先读取苹果 content-language 的纯色贝塞尔形状；没有该数据时尝试单页填充路径 PDF。已验证实际复制的单个三路径人物与八个成组主题对象，输出均为真实矢量路径。图片、文字、渐变、描边、透明度效果，以及旋转或翻转的成组对象暂不支持，会明确报错并拒绝部分导出。不会把 TIFF/HEIF 预览图片当作矢量 SVG。只在用户触发导入时读取剪贴板，不监听或上传剪贴板。

### 复制 SVG 与导出状态（0.6.1）

右键预览卡片选择「复制 SVG」可复制当前图标；右侧「复制 SVG」复制所有勾选图标。两种方式均保留当前调色、透明背景和矢量路径。剪贴板按图标分别写入 SVG 数据、SVG 源码文本和实际 SVG 文件引用；文件保存在应用缓存中，便于接收应用在粘贴时读取。

「导出 Keynote」「导出 SVG」「复制 SVG」使用统一样式，竖直排列在右侧同一列。「在 Finder 中查看」仅在本次文件导出成功且目标存在后显示；导入新素材、清空列表或开始新导出会清除旧位置，复制 SVG 不会创建导出成功状态。

### 右侧布局（0.6.2）

左侧导入栏保持原样。右侧上方显示图标选择、调色与预览，预览下方显示状态提示；底部左侧显示当前素材名称，右侧上排导出方式和 ZIP，下排统一竖排 Keynote、SVG 和复制 SVG 按钮。

0.6.3 移除右侧底部重复的大号素材名称，名称继续在左侧列表和预览卡片中显示。


0.6.4 将右侧操作集中到顶部：选择与导出选项在上方，预设颜色和自选颜色分两行，三个操作按钮竖排在右上角。取消底部大块操作区，预览网格使用剩余空间，按实际图标数量和窗口宽度排列；左侧栏保持原样。
